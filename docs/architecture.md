# 设计与实现

## 为什么这里使用 Agent

用户可能问单个数字、跨年差异、统计口径或多个监管条款。所需步骤取决于检索返回内容：模型需要判断是否改写查询、查阅原文、计算，或将独立子问题委派给子 Agent。这部分使用 ReAct 循环。

文件上传、解析入库、账号鉴权、幂等校验、事务、索引状态、SSE 和审阅使用确定性代码，不让模型决定权限或数据库状态。

## 一次请求的完整路径

1. Spring Security 会话确定用户；Controller 校验输入，Service 核验会话与文档归属及索引状态。
2. MySQL 以 `(owner_id, idempotency_key)` 唯一约束保障任务唯一；相同键不同请求摘要返回冲突。
3. 提交线程立即返回任务 ID。有界任务线程池运行主 Agent；对云模型的等待不处于数据库事务内。
4. 模型返回工具调用。只读检索/读取和有明确输入的计算可并发；依赖前一结果的操作在下一轮执行。子 Agent 在独立线程池运行，避免父子等待耗尽同一个线程池。
5. Python 先按 owner 和授权 document IDs 确定检索范围，中文 BM25 与稠密向量各取 Top 20，以 RRF 合并去重后返回 Top 8。任一检索分支失败即显式报错，不悄悄降级。
6. 工具结果与 Agent 记录保存到 MySQL。SSE 事件先落库再发送，断线从事件 ID 继续读取，不重新执行任务。
7. 最终答案必须非空且经过实际工具调用；引用 ID 必须存在于本任务授权证据中。证据不存在时将校验失败作为下一轮观察返回模型，在原有步数预算内修正；步骤耗尽仍失败，不放宽校验。若计算工具失败，必须重新计算成功才允许完成。模型使用任务内短引用编号，后台保留完整原文片段 ID。
8. 用户点击引用可看片段并打开 PDF 页码或文本段落；人工确认/修正以独立审阅记录保存，事务内同步更新状态，版本冲突拒绝覆盖。

## Multi-Agent 的边界

`delegate` 启动独立 ReAct 子循环，拥有单独 system/user 消息、工具历史、步数和数据库 agent_run，`parent_id` 建立真实父子关系。父子共享当前任务的取消信号和已取得证据，但子 Agent 只能访问明确授权的文档子集；子工具集中没有 delegate。

会话用于任务归档，不自动把历史任务回答拼接进新任务上下文。

主 Agent 最多执行 12 轮工具探索、子 Agent 最多执行 8 轮工具探索；探索预算耗尽后进入独立的强制收敛阶段，不再向模型暴露工具，只允许其依据已取得证据生成最终答案。同任务最多 2 个并发子 Agent。不是固定“规划—执行—总结”三个角色，也不是把多次工具调用改名成多个 Agent。

## 调度和持久化

| 线程池 | 工作线程 | 排队容量 |
| --- | ---: | ---: |
| 主任务 | 2 | 16 |
| 子 Agent | 4 | 8 |
| 模型调用 | 6 | 12 |
| 普通工具 | 8 | 32 |
| 文档索引 | 2 | 8 |

队列使用 AbortPolicy。CompletableFuture 关联实际 FutureTask，取消会尝试中断底层工作；Java HttpClient 设置连接及请求超时。取消不会保证云端已经开始的计算停止计费，但会停止本地后续步骤，终态不可被迟到结果覆盖。任务总时限 10 分钟。

上下文以 24,000 字符预算控制，先移除旧的完整 assistant/tool 组，必要时显式截短工具正文；保留调用与返回配对，完整记录在数据库。字符预算不是精确 tokenizer token 数，也不保证提高回答准确率。

应用重启保留历史，将未完成任务、工具与索引标记中断；不会自动重跑产生费用。MySQL 和 Qdrant/文件不组成分布式事务，仅在索引全部成功后允许文档参与检索。

## 安全与限制

- BCrypt 密码、服务端会话、CSRF、资源归属过滤；模型不能自行授予权限。
- 内部检索服务仅监听 127.0.0.1，要求内部访问令牌；密钥在本机受限文件中，不进入源码与界面。
- HTML 内容经过文本提取，原文查看采用转义后段落展示并限制脚本；不执行上传内容。
- 引用校验验证“引用存在且有权限”，不能替代对论断是否被证据支持的人工核对。
- 计算采用 BigDecimal，限制操作集；对单位/年份的语义理解仍依赖模型和人工审阅。
- Qdrant 是开发用本地模式，不宣称集群、高可用或生产多租户隔离；本版不包含独立 Qdrant 服务部署。
- 公开仓库只分发合成样例；本地验收使用的真实文件不进入版本库。大文档首次向量化需要等待。只支持文字层 PDF；HTML/TXT 使用 UTF-8。

## 工作台附件与单任务范围

上传前用户明确选择 `LIBRARY` 或 `TASK`，保存到 `documents.storage_scope`。资料库查询只返回 `LIBRARY`；后台返回的附件元数据不包含磁盘路径。原文与附件状态接口仍校验用户归属。

`TaskService` 使用短事务一起插入任务和认领附件：`UPDATE documents ... WHERE storage_scope='TASK' AND task_id IS NULL AND status='READY'`。更新失败就回滚整个事务；按排序后的文档 ID 认领避免反向锁序。幂等重试返回原任务，新的请求不能再次绑定同一附件。模型工具只能接收已通过这一步授权的文档 ID，子 Agent 只能继续缩小范围。会话历史不自动带入新任务。

模型调用在事务提交后执行。若任务队列已满，返回已落库的 FAILED 任务及原因，前端清空已消费附件，避免把“已绑定但执行未开始”的附件误当成还能提交的草稿。

未提交附件移除时先标记 DISCARDED，阻止新任务认领；清除原文件与检索索引。索引工作返回后再次检查状态、清除迟到结果，不能把已移除附件改回 READY。已绑定附件不提供草稿删除入口，随任务保留原文件和证据以便历史追溯；当前不是敏感文件执行后自动销毁方案。

PNG/JPG 经 macOS Vision OCR 提取中英文文字，片段明确标记 OCR，图片原文接口返回原图。限制单边 16000 像素、总计 3200 万像素，识别超时 60 秒。无文字、损坏图片、未安装 OCR 会明确失败；不将其伪装成成功索引，也不切换其他识别服务。图表语义、多栏复杂表格和数字识别仍需人工核对。实现依据 Apple `VNRecognizeTextRequest` 文档：https://developer.apple.com/documentation/vision/vnrecognizetextrequest 。
